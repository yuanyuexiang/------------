# 项目工作台流程与追溯设计

## 交互原则

主流程收敛为“核对采购信息 → 准备投标文件 → 检查并导出”。未确认采购信息时进入核对页，已确认则进入文件准备。项目时间、备注、结果及操作记录通过顶部“项目信息”查看。资格摘要融入资料准备，详细检查依据按需展开。准备页以商务、技术文件为主体，直接生成；生成后的检查页优先显示文件及问题。每页保留一个主要操作，生成和正式导出继续执行既有条件检查。

参考依据：GOV.UK 的 [Task list](https://design-system.service.gov.uk/components/task-list/) 与 [Check answers](https://design-system.service.gov.uk/patterns/check-answers/)，以及 SAP Fiori 的 [Object Page](https://www.sap.com/design-system/fiori-design-web/v1-136/ui-elements/object-page/)。这些模式提供任务组织和复核方法；本项目的投标业务适配仍需真实用户验证。

## 要求、证据与响应

采购原文通过核对页的“查看采购原文”打开，默认不占据主页面。准备和检查页面的详细区域保留本包要求清单，不要求用户逐条维护关联。打开条目后，可同时查看采购要求及原文内容、当前选择的企业证明材料、当前生成版本的响应文件。响应位置使用稳定段落或表格标识，不推测 Word 页码。核对人可保存关联、备注及人工核对状态。记录包含操作人和时间。

清单覆盖已解析要求，不代表原件所有要求都已抽取。附件关联不等于资格通过，单条人工核对不等于整份文件合格；正式导出继续执行原有门禁。来源为资格表的数据目前通过原件压缩包核对，不提供虚构的 Excel 原文预览。Word 内容预览显示段落和表格，图片数量会提示；精确排版、签章与图片请下载原件核对。

## 数据与失效规则

关联保存在项目结果 JSON 中，按企业、分包、要求标识隔离。保存时同时校验输入版本和条目修订，避免后台变更或多人操作覆盖记录。材料变更、响应版本变化及文件内容变化会提示重新核对。文件预览只允许当前企业和分包的最新生成清单文件，并验证文件哈希。

资格结果按分包保存检查依据，包括实际采用的资质、人员、业绩、检测报告与附件。修改联系电话等不参与资格判断的信息不再使资格报告失效；改变某包选材只影响相关包。采购要求、截止日期或所用证明变化仍须重新检查。历史报告缺少分包依据时保留保守失效逻辑。

## 验证

后端回归覆盖关联保存、企业及分包隔离、并发修订、材料变更、文件哈希、响应位置与原件读取限制。前端执行类型检查、构建及现有规则测试；使用独立合成项目在浏览器验证任务入口、原文对照、关联保存及恢复、准备事项跳转和响应预览，避免修改真实投标资料。

简化界面额外检查三项主导航、项目直接进入当前工作、采购确认后进入准备、原文按需打开、响应文件预览、旧资格页链接跳转及窄屏布局。此次简化仅调整前端组织与入口，不修改解析、生成或正式导出的领域规则。
