# Jinbang（金榜）用户使用手册

> 适用对象：使用 Jinbang 完成国家电网投标文件分析、资格自检、文件生成与合规复核的业务人员。  
> 手册版本：V1.0（依据 2026-08-25 系统原型编写）

## 1. 系统能做什么

Jinbang 是供应商自用的国网智能投标管理系统。系统以招标文件解析结果 TRM（招标要求模型）为主线，协助完成：

1. 导入 ECP 下载的招标文件压缩包；
2. 提取批次、分包、截止时间、资格条件、否决条款、技术参数和递交要求；
3. 由业务人员逐项确认解析结果；
4. 使用企业知识库进行资格自检；
5. 生成商务文件和技术文件，并自动填写可确定的参数；
6. 检查否决风险、扣分项、缺失材料和待人工确认项；
7. 进行技术、商务模拟评分，形成提分提示；
8. 查看递交矩阵并导出文件；
9. 记录项目截止时间、进展、结果和操作时间线。

系统遵循两个重要原则：

- **事实只来自企业档案**：企业资质、人员、业绩、产品参数等不会由模型凭空生成。
- **人工确认优先**：机器解析、资格判断、生成内容和模拟评分均为辅助结果，最终应以招标原文和业务复核为准。

## 2. 使用前准备

开始一个正式项目之前，请准备：

- 从 ECP 下载的完整招标文件包，格式为 `.zip`；
- 本企业的基本信息、证照、人员、业绩、财务、产品和检测报告资料；
- 证照、合同、发票、检测报告等证明文件的 PDF 或图片扫描件；
- 招标经办人提供的系统地址、用户名和初始密码；
- 如需 LLM 解析兜底、业绩语义匹配、技术方案起草或软项评分，由管理员提前完成 LLM 配置。

建议先维护企业知识库，再导入正式项目。档案不完整会造成资格自检出现“需人工”，生成文件出现“【待补充】”，并可能阻断导出。

## 3. 登录与账户

### 3.1 登录

1. 在浏览器打开系统地址。
2. 输入用户名和密码。
3. 单击“登录”。
4. 首次登录或管理员重置密码后，系统会强制要求修改密码。新密码至少 6 位。

如连续登录失败，请确认用户名、密码以及账户是否被管理员停用。

### 3.2 角色与权限

系统有两种角色：

| 角色 | 主要权限 |
|---|---|
| 管理员 | 使用投标业务功能；维护知识库；修改配置中心；管理用户；天然可见价格数据 |
| 成员 | 使用投标业务功能；维护知识库；查看配置；是否可见价格由管理员单独授权 |

右上角用户菜单可修改密码或退出登录。涉及价格的页面和数据仅对有“可见价格”权限的用户开放。

## 4. 推荐操作流程

正式投标建议按以下顺序操作：

**维护企业知识库 → 导入招标文件 → 检查项目时间 → 确认 TRM → 资格自检 → 决定是否参投 → 生成文件 → 补齐材料 → 合规审查 → 模拟评分 → 核对递交矩阵 → 导出 → 人工终审与递交 → 登记项目结果**

不建议跳过 TRM 确认。下游功能虽然可以运行，但只有保存人工确认版后，资格自检、生成和审查才会稳定使用经业务人员核对的数据。

## 5. 企业知识库

知识库是投标文件事实数据的唯一来源。左侧选择“企业知识库”进入。

### 5.1 新建企业档案

1. 单击“新建企业”。
2. 输入企业名称和统一社会信用代码。
3. 保存后进入企业详情。

供应商自用场景通常只需维护本企业一份档案。删除企业档案会同时移除其业务条目，请谨慎操作。

### 5.2 填写主档

在“主档”页维护统一社会信用代码、法定代表人、负责人、企业性质、成立时间、注册资本、被授权人、地址、银行账户、联系方式、人员规模和经营范围等信息，完成后单击“保存主档”。

信息应与营业执照、开户证明及正式投标材料一致。不要为了通过检查填写未经证实的内容。

### 5.3 维护业务资料

知识库包含以下分类：

| 分类 | 建议重点维护内容 |
|---|---|
| 证照 | 名称、类型、编号、等级、发证机关、起止日期、审核状态、出处 |
| 人员 | 姓名、职务/职称、专业、学历、社保单位、可投入状态及身份证、学历证、社保证明等证件 |
| 业绩 | 项目、买方、最终用户属性、金额、签约日期、物料类别、电压等级及合同、发票等证据 |
| 财务 | 年度、营业收入、净利润、总资产、资产负债率 |
| 产品 | 型号、名称、物料类别、参数名与具体值、功能特性、关联检测报告、适配规范 ID |
| 检测报告 | 报告名称、类型、机构、编号、日期、有效期、覆盖型号 |
| 话术库 | 已审核的售后、质量、培训、保密、应急或实施方案段落 |

每条资料建议填写“出处”，例如文件名和页码，便于复核。需要参与自动引用的内容应设置为已审核或 approved。

业绩资料尤其要确认：买方是否为最终用户、合同和发票是否齐全、签约日期是否落在招标要求年限内。缺少这些字段时，系统通常只能给出“需人工”结论。

产品“参数表”按“参数名=值”逐行录入。参数值应为可直接写入技术参数响应表的确定事实。

### 5.4 上传附件

1. 进入“附件库”。
2. 先选择归类，如证照、人员、业绩或检测报告。
3. 拖入 PDF 或图片。
4. 上传后可在相应资料条目中挂接附件。

系统会按内容对同一文件去重。删除附件后，已挂接的条目会失去该证明文件。

### 5.5 检查有效期

“有效期看板”汇总证照和检测报告的状态，可选择 30、60、90、180 或 365 天预警范围，也可输入计划开标日，按开标日判断届时是否有效。

状态包括已过期、30 天内、60 天内、90 天内、有效和未录入。“未录入”不等于有效，应及时核对原件并补录。

## 6. 导入招标项目

### 6.1 上传文件

1. 左侧选择“投标项目”。
2. 将 ECP 下载的 `.zip` 文件拖入“导入招标文件包”区域。
3. 等待进度条完成。系统支持批次级和包级压缩包。
4. 出现“解析完成”后，在项目列表中打开项目详情。

建议上传原始完整压缩包，不要随意删除目录或改写文件内容。不要上传企业档案、报价文件或与招标无关的压缩包。

### 6.2 解析失败处理

如显示“解析失败”：

1. 记录页面上的错误信息；
2. 确认文件确为 ZIP 且能够正常解压；
3. 检查压缩包是否损坏、加密或缺少主要招标文件；
4. 重新从 ECP 下载后再次上传；
5. 仍失败时，将错误信息和文件结构说明交给系统管理员排查。

系统中的项目删除操作会删除项目记录及产出文件，执行前会二次确认。

## 7. 项目详情与时间管理

项目详情页展示当前阶段、各分包进度、关键时间、产出文件和操作时间线。

### 7.1 核对关键时间

系统会尝试从招标公告抽取投标截止时间。请立即与招标原文核对：

- 投标截止时间；
- 开标时间；
- 时区和日期格式；
- 是否存在延期、澄清或变更公告。

如抽取错误或为空，可人工输入 `YYYY-MM-DD HH:MM` 并单击“保存时间”。项目列表会按剩余天数显示提醒：3 天内为红色、7 天内为橙色。

### 7.2 维护项目状态

可填写项目备注，例如负责人、分工、联系人和特殊注意事项。投标结束后，将结果更新为“已递交”“中标”“未中标”或“放弃”。

“在投 / 已结束 / 全部”用于筛选项目。时间线会保留解析、确认、自检、生成、审查、评分、导出及结果变更记录。

## 8. 确认 TRM

TRM 是系统对招标要求的结构化表达，也是后续流程的依据。

1. 在项目列表单击“确认 TRM”，或在详情页单击同名按钮。
2. 先查看顶部警告、批次号、统计数量和术语体系。
3. 逐项核对“关键条件”。重点检查投标截止、开标、有效期、保证金、限价等关键事实。
4. 按标包检查：
   - 项目与分包名称；
   - 资格条件和业绩要求；
   - 货物清单、数量、交货时间和规范书 ID；
   - 技术参数，尤其标有“★”的关键参数；
   - “投标人保证值”是否已有可靠数据。
5. 查看“否决规则”“提交方式表”和“前附表”，与原文抽样核对。
6. 对页面允许编辑的字段进行修正。
7. 单击“确认并保存为人工确认版”。

出现“批次号未抽到”、空值、警告或“非结构化·附件逐项响应”时，不应直接忽略。请回到原始招标文件人工核对；无法结构化的规范书需要按附件逐项响应。

## 9. 资格自检

1. 进入项目的“资格自检”。
2. 选择企业档案。
3. 按需开启“LLM 业绩语义匹配”。未配置 LLM 时关闭该开关。
4. 单击“运行资格自检”。
5. 逐包查看结论和证据。

结论含义：

| 结论 | 含义与建议 |
|---|---|
| 可投 | 当前档案未发现明确不满足项，仍需人工终审 |
| 有风险 | 存在风险、信息不足或需要业务判断，补证后重跑 |
| 不可投 | 发现明确不满足条件，应核对原文和证据后决定放弃、澄清或采取其他业务措施 |

单项状态包括“满足”“风险”“不满足”和“需人工”。每项会显示说明、证据及要求原文。带“LLM”标签的匹配是语义辅助判断，不可代替合同、发票和招标原文审查。

如资料不足，可单击“补全档案”进入对应企业业绩页，补录后重新运行自检。

## 10. 生成与审查工作台

### 10.1 生成文件

1. 选择企业档案。
2. 选择要处理的分包。
3. 按需开启“LLM 起草技术方案”。
4. 单击“生成商务/技术文件”。
5. 等待任务完成，并查看生成结果。

未开启 LLM 时，系统仍可执行确定性填充和文件生成；开启后可生成带溯源的技术方案草稿，但仍需专业人员审阅。

### 10.2 处理“【待补充】”

“文件与待补充”页会列出每个文件的缺失项。只要存在“【待补充】”，系统会阻断正式导出。

处理方法：

1. 根据待补充清单找到缺失事实或材料；
2. 回到企业知识库补录并挂接证据；
3. 必要时在 TRM 确认页修正招标要求；
4. 重新生成文件；
5. 确认待补充数量为 0。

不要在不核实来源的情况下直接删除“【待补充】”字样。

### 10.3 核对技术参数响应

技术参数响应按规范书展示项目需求值、投标人保证值、判定和说明。判定包括：

- 满足：现有产品参数可明确满足；
- 偏差：现有数据与要求存在冲突；
- 待确认：信息不足或规则无法确定；
- 待补充：没有可用事实值。

所有“★”参数、偏差、待确认和待补充项都应由技术负责人逐项复核。

### 10.4 合规审查

生成完成后单击“合规审查”。结果分为：

- **否决**：可能导致投标被否决，通常会阻断导出；
- **扣分**：可能影响评分；
- **建议**：优化建议；
- **需人工**：系统不能确定，需要业务人员确认。

每条发现包含规则编号、问题说明、位置和依据。应对照招标原文逐条关闭风险，而不是只看“无否决项”汇总标签。

### 10.5 模拟评分

单击“模拟评分”查看技术和商务预测、评分区间、方法、依据和缺失证据。加权结果默认不含价格时，页面会明确标注。

模拟评分用于识别材料短板和提分方向，不是评标结果承诺。若评分细则缺失或模板匹配错误，应由管理员在配置中心维护正确模板后重新评分。

### 10.6 递交矩阵

单击“递交矩阵”，核对每项文件的递交通道、投标工具端口和当前状态。递交前应将此矩阵与第六章提交方式表、ECP 页面和最新澄清文件交叉核对。

### 10.7 导出

工作台的“整改与正式导出”区域会列出阻断原因。正式导出必须同时满足：TRM 已人工确认；文件为本包最新生成版本，所用 TRM、企业档案、附件和项目时间未变化；当前规则下的本版本合规审查无否决项；本包所有生成文件（含页眉页脚、嵌套表格）无“【待补充】”。系统不接受强制绕过检查。

发现问题后，按“核对招标要求 → 补齐企业资料 → 重新生成 → 复查本版本”整改。修改资料后需要重新生成本包文件；只修改规则配置时，重新审查即可。每次生成保留独立版本，工作台刷新后会恢复最近版本与完整问题清单。旧系统生成的文件没有版本记录，需要重新生成、审查后才能正式导出。

通过检查后，在文件旁单击“正式导出（Word / PDF）”。系统在副本上清理元数据，并在页面提供正式 Word 下载链接；PDF 转换成功时同时提供 PDF 链接，未配置转换服务或转换失败时会明确提示。原始草稿可下载核对，但不代表已通过正式导出检查。资料或规则变化后，旧正式件的下载链接也会被阻断。

下载后必须进行人工终审，包括：

- 文件是否能正常打开，目录、页码和格式是否完整；
- 企业名称、授权人、日期、签章位置是否正确；
- 分包号、项目名称、报价与技术参数是否对应；
- 是否残留“【待补充】”、批注、修订、隐藏文字或模板说明；
- PDF 与 Word 内容是否一致；
- 文件名、大小、格式和递交端口是否符合要求；
- 电子签章和加密是否按投标工具要求完成。

系统目前不代替 ECP 或投标工具 U+ 完成最终上传和递交。

## 11. 配置中心

成员通常只读，管理员可修改。配置变更可能影响所有项目，应记录依据。

### 11.1 评分模板库

解析招标文件时，有详细评审要素的模板会自动入库。管理员也可：

- 手工新建或编辑模板；
- 上传 `.xlsx` / `.xls` 评分细则；
- 选择是否允许同名覆盖；
- 维护技术、商务、价格或其他类型及各评分区间。

模板按名称匹配。发现项目引用名称与模板不一致时，应先修正模板或招标要求，再重新评分。

### 11.2 否决规则库

管理员可以启停规则、覆盖级别、调整参数或恢复默认。停用或降低否决规则意味着该类问题可能不再阻断导出，仅在确认本批次确实无该要求时操作，并在备注中写明招标条款依据。

### 11.3 LLM 设置

页面可配置兼容 OpenAI 的端点、模型、温度和超时，并测试连接、查看调用量及错误记录。API 密钥只能由管理员写入服务器环境变量，不能在页面录入。

LLM 未配置或连接失败时，解析兜底、语义匹配、起草和软项评分不可用，但确定性解析与填充功能仍可使用。

## 12. 用户与权限（管理员）

管理员可新建、编辑、停用或删除用户，设置角色及价格可见权限，也可重置密码。新建用户和密码被重置的用户，下次登录时必须修改密码。

不要共用账号。每位操作人员使用独立账户，项目时间线才能准确记录操作人。管理员不能删除或停用当前登录的自己。

## 13. 常见问题

### 上传后长时间停在解析中怎么办？

先刷新项目页并查看项目详情中的任务状态。仍无进展时记录任务消息，由管理员检查后端任务服务。不要连续重复上传同一个大文件。

### 为什么资格自检大量显示“需人工”？

通常是企业档案缺少最终用户、签约日期、合同/发票证据、证照有效期或人员证明。补全这些字段并重新运行。

### 为什么技术参数大量“待补充”？

产品档案中没有与规范书要求对应的参数，或参数名称、型号、规范 ID 无法匹配。补全产品参数并确认关联型号后重新生成。

### 为什么不能导出？

文件中仍存在“【待补充】”或命中阻断规则。查看待补充清单和合规审查的否决项，补齐后重新生成、审查和导出。

### LLM 开关打开后报错怎么办？

在配置中心查看密钥状态和最近调用错误，请管理员测试连接。业务流程可暂时关闭 LLM 开关，继续使用确定性功能。

### 修改企业档案后，旧文件会自动更新吗？

不会。知识库更新后需要重新运行资格自检或重新生成文件。

### 模拟评分能否作为投标决策的唯一依据？

不能。它用于内部预判，受评分模板、档案完整度和软项判断影响，最终以评标委员会结果为准。

### 系统是否会自动提交投标文件？

不会。系统提供生成、检查、导出和递交矩阵，最终签章、加密、上传和递交仍需在官方工具中人工完成。

## 15. 使用边界与安全提醒

- 系统输出是投标辅助材料，不构成对资格通过、中标或评分结果的保证。
- 当前解析准确率仍依赖业务专家持续标注和校验，不能省略原文复核。
- 服务类叙述式规范书、扫描质量差的附件和特殊格式文件可能无法完整结构化。
- 前端目前不提供完整的 Word 在线编辑；需要在下载后的 Word/WPS 中完成排版和签章，再进行终审。
- 不要上传与业务无关的个人敏感信息；企业证照、合同和客户资料应按公司数据安全制度管理。
- 不要将账号密码、API 密钥、原始招标 ZIP、客户数据或生成文件提交到代码仓库或发送给无权限人员。

如页面结果与招标原文冲突，以最新正式招标文件及澄清通知为准，并将异常反馈给系统管理员。
