# Jinbang（金榜）· 原型开发计划

> 项目开发代号：**金榜（Jinbang）**，即"国网智能投标 Agent 系统"。

**版本**：v1.0　**日期**：2026-08-21　**依据**：《国网智能投标Agent系统-完整技术方案.md》第 9 节
**周期**：10 周（5 个 Sprint × 2 周），预留 1 周缓冲
**团队**：后端 ×2（含 1 名兼架构）、算法/Prompt ×1、前端 ×1、业务专家 ×0.5、测试 ×0.5

---

## 0. 原型目标与验收总标准

用本地真实样本端到端跑通一条完整投标流水线：

```
导入招标文件包 → 解析 → TRM人工确认 → 资格自检 → 生成商务/技术/价格文件 → 合规审查 → 模拟评分 → 导出
```

**总验收（Demo Day，第 10 周末）**：业务专家扮演标书专员，对一个从未参与开发调试的标包，40 分钟内完成导入到导出全流程；生成文件与真实投标文件成品结构一致；预埋 20 处典型错误拦截 ≥95%。

**固定测试集**（`物资/`、`服务/` 目录，开发期间冻结不改）：

| 编号 | 样本 | 用途 |
|---|---|---|
| TS-1 | 陕西物资集招 W-2026-SNGW-Z03（选 3 个分标：综合网管/UPS/模块化数据中心） | 物资类主测试线 |
| TS-2 | 国网信通中心物资第三次 | 解析泛化验证 |
| TS-3 | 江苏服务第四次公开招标 包147/148（含投标文件成品） | 服务类主测试线 + 输出对照基准 |
| TS-4 | 福建服务竞谈 包16（含应答文件成品、评分细则 xlsx） | 竞谈术语变体 + 评分字典来源 |

**测试企业档案**：以样本中真实投标文件成品的公开信息为蓝本，构造一家虚拟企业"测试企业A"的完整建档数据（主档/证照/人员/业绩/产品/报告），Sprint 2 前由业务专家准备完毕。

## 1. 技术底座（Sprint 1 第 1 周并行搭建）

| 项 | 决定 |
|---|---|
| 仓库 | 单体仓库 `jinbang/`：`apps/jb-api`（FastAPI）、`apps/jb-web`（React+Vite）、`packages/jb-parser`、`packages/jb-kb`、`packages/jb-docgen`、`packages/jb-rules`、`packages/jb-agents`、`tests/fixtures`（指向测试集） |
| 存储 | PostgreSQL 15（+pgvector+zhparser）、Redis 7、MinIO；docker-compose 一键起 |
| 前端栈 | React 18 + TS + Vite + Ant Design 5 + TanStack Query + Zustand + ECharts；docx 审阅用"转PDF+pdf.js预览+章节级重跑"，不做在线编辑器 |
| 中间件 | LibreOffice headless 容器（docx→PDF）、Xinference（BGE-M3+reranker，可先用云API）、**LiteLLM Proxy 作为 LLM 网关**（多模型接入/记账/限流，Agent 只面向 OpenAI 兼容接口）、Nginx 反代（大文件上传分片） |
| 明确不上 | Kafka/ES/Milvus/K8s/微服务拆分/WebSocket（轮询够用）/在线docx编辑；可观测性 = structlog + LiteLLM 记账，Sentry 可选。目标：7 个容器跑起整系统 |
| LLM | 先接 API（Qwen/DeepSeek 国内合规云）走统一网关层，私有化后期切换；所有调用带项目/模块标签记账 |
| 任务 | Celery（解析、生成、审查均为异步任务，前端轮询/推送） |
| 质量 | pytest + 解析准确率回归集；关键引擎（数值比较、金额大小写、规则引擎）单测覆盖 ≥90%；CI 跑全量 fixture 回归 |
| 文档转换 | LibreOffice headless 容器（docx→pdf） |

## 2. Sprint 计划

### Sprint 1（第 1–2 周）：解析器 + TRM

**目标**：TS-1~TS-4 四套样本 → TRM JSON，准确率 ≥90%。

| # | 任务 | 负责 | 产出 |
|---|---|---|---|
| 1.1 | 包解压器：递归 zip、cp437→gbk 文件名、文件分类器（主docx/公告/规范书/清单/评分细则/合同/sign） | 后端A | `parser.unpack` |
| 1.2 | 六章切分 + 条款号定位（前附表 77 行、否决表 46 行、提交方式表 50 行按表格直读） | 后端A | `parser.chapters` |
| 1.3 | xlsx 附件读取（货物需求/资质业绩/货物清单，表头第 3 行规则；合并单元格处理） | 后端B | `parser.sheets` |
| 1.4 | 技术规范书解析：三段式识别、标准技术参数表逐行结构化（★识别、单位、需求值）、结构化/非结构化判别（ID 前缀） | 算法 | `parser.spec` |
| 1.5 | LLM 抽取兜底：资格条款、否决条款语义归一到规则库分类；JSON Schema 校验与重试 | 算法 | `parser.llm_extract` |
| 1.6 | TRM Schema（Pydantic）+ 落库 + 交叉校验（分值和/时间序/包-规范书ID对齐） | 后端B | `models.trm` |
| 1.7 | 人工标注基准：业务专家对 4 套样本手工标注 TRM 关键字段作为准确率基准 | 业务 | `tests/golden/` |
| 1.8 | 竞谈术语变体适配（应答人/开封） | 后端A | — |

**验收**：`pytest tests/parser` 全绿；对 golden 集字段级准确率报告 ≥90%；单批次解析 ≤5 分钟。

| 2.3 | "测试企业A"完整建档（照建档 Checklist） | 业务 | 测试档案 |

## 4. 风险应对（开发视角）

| 风险 | 触发信号 | 预案 |
|---|---|---|
| S1 解析准确率上不去 | W2 中检 <80% | 缩小自动化范围：难字段转确认页人工补录，不死磕 |
| docx 样式还原不达标 | S3 对照测试红 | 切 Aspose.Words 商用授权（预算预案），或该表格改"填 PDF 模板" |
| LLM 输出不稳 | Schema 重试率 >20% | 收窄单次任务粒度+few-shot 固定样例；关键表格全部走规则不走 LLM |
| 业务专家投入不足 | golden/建档延期 | 里程碑依赖提前两周排期；标注工作拆小可并行 |

## 5. Definition of Done（每 Sprint 通用）

代码合并主干且 CI 绿；fixture 回归无退化；新功能有业务专家验收记录；文档（API/数据变更）同步更新；Demo 环境可复现。
