## 2. ECP 招标文件包的物理结构（解析器输入规范）

```
<批次名>_招标文件包.zip
└─ 分标NNN<分标名>/                          ← 物资按分标组织；服务按 <类别>/包NNN
   └─ 包N_完整招标文件_<18位ID>.zip
      ├─ 招标文件(W-2026-SNGW-Z03物资).docx  ← 主文件（服务类叫"服务公开招标文件分册-NNNNNN.docx"
      │                                        或"…竞争性谈判采购（应答总价）采购文件.docx"）
      ├─ 招标公告.zip
      │  ├─ 第一章 招标公告（三批）.docx
      │  ├─ 附件1/2：货物需求一览表.xlsx     ← 分标/包/物料编码/技术规范书ID/最高行限价/交货
      │  └─ 附件3：资质业绩一览表.xlsx       ← 每分标：业绩要求+资质要求(试验报告/关键参数/生产设备/
      │                                        试验设备/认证证书/许可证)+是否接受代理/集货商
      ├─ 包N_技术规范书_<ID>.zip
      │  └─ <采购申请描述>(<技术规范书ID>)<n>.zip   ← 再嵌套一层 zip！
      │     └─ …/技术规范书.docx（每个采购申请一本；可能附 报价表.xls、图纸）
      ├─ 合同文件.zip                         ← 合同专用+通用条款 docx
      ├─ 货物清单_<批次>_<分标>….xlsx         ← 行项目级：分标编号(262603-xxx-9999)/包/项目单位/
      │                                        物资描述/数量/交货日期/交货地点/交货方式
      ├─ 评分细则（NNNNNN）.zip               ← （福建服务样本）价格/商务/技术评分模板
      └─ bidpkgsignYYYYMMDD_HHMMSS_mmm.sign   ← 招标文件包数字签名文件
```

解析器必须处理的工程细节：

1. **zip 内文件名是 GBK 编码**（非 UTF-8），解压需 `cp437 → gbk` 转换，否则乱码/失败。
2. **多层嵌套 zip**（招标文件包 → 包 zip → 技术规范书 zip → 采购申请 zip），需递归解压。
3. **一包多本技术规范书**：陕西综合网管包1 对应 3 个采购申请、3 本规范书（ID 如 `B006-500009678-00011`、`D068-500009678-00001`），行项目通过货物清单的"技术规范书ID"关联。规范书 ID 格式 `<前缀>-<物料编码>-<序号>`；前缀 9999 开头为固化/结构化规范（见典型案例库），样本中还有 B006/D068/D03S/D06E/B00D 等项目规范。
4. `.sign` 签名文件、`.DS_Store` 等直接忽略；xlsx 表头通常在第 3 行（前两行是标题）。
5. 服务竞谈的术语整体替换：投标人→应答人、投标文件→应答文件、开标→开封，结构不变。

## 3. 招标文件 docx 章节结构（已验证）

六章结构与方案假设一致（陕西物资版实测）：

```

第五章 供货要求        ← 指向技术规范书
```

**条款号体系与典型案例库完全对上**：案例库引用的 1.11.2/1.11.4（技术参数逐项响应）、3.1.2（否决情形）、3.4.1（保证金）、8.2（串通投标认定）在真实文件中逐一找到，说明国网范本条款号全网统一，**可以做成静态条款字典**，解析时只需定位差异。

### 3.2 否决情形表（评标办法前附表之二，46 行，全文已提取）

分四类：**形式评审**（格式内容/文件签署/电子签章/参数接口）、**响应性评审**（澄清修改/交付期限/报价 6 条/担保/范围/偏差/有效期/税率/实质不符）、**资格评审**（虚假投标-全部标包连坐、串通、法定否决、质量事故、失信惩戒×2、行贿记录、不良行为+熔断、专用资格、代理商规则×2、资质能力核查、利害关系×5、名称不一致、同法人/控股×2、资信不良、无效代理、丧失履约能力）、**其他**。与方案第 8.2 节 22 条规则库高度吻合，另补充了此前没有的：

- 一个制造商对同一品牌同型号货物委托两个及以上代理商投同一包 → 否决；制造商与其代理商同包 → 否决
- 投标人名称与执照/资质证/许可证不一致且无变更证明 → 否决
- 与监理人/代建人/招标代理同法人或控股参股关系 → 否决
- 主要技术参数/产品型式不满足、一般参数超允许偏差范围、接口（一次/二次/土建）响应不符 → 否决（即一般参数允许小偏差、主要参数零容忍的分级规则）

### 3.3 第六章投标文件格式 + 提交方式表（递交矩阵官方原版）

第六章末尾有一张**50 行提交方式表**：序号|内容|提交方式(电子商务平台/省辅助系统)|是否有格式要求|**投标工具上传端口**。实测结构：

- **价格文件（按包制作）**：投标函及附件、已标价货物清单行报价暨投标报价汇总表（"供应商投标工具按包投标后自动生成"）、货物清单单价分析表（"维护单价分析表"页签）——**价格全部在投标工具内完成，系统只做校验与底稿**
- **商务文件（按分标制作）**：投标函、商务偏差表、补充文件（汇款凭证/基本账户证明）、与国网系统人员关系说明、基本情况表、营业执照、税务登记、资格证明+查询报告截图、财务状况、商务评分支撑材料、名称变更说明、制造商授权、财务信息审核凭证单、投标专用章授权、**配合资质能力核实承诺函**、法人授权委托书、投标保证信用承诺书
- **技术文件（按包制作）**：技术偏差表、业绩文件、技术特性参数表、货物组件材料配置表、资格证明、技术评分支撑材料、技术服务/培训、售后服务承诺、质量保证措施、生产场地产能、生产装备、调试试验场所与检测设备、制造工艺、认证证书、主要技术人员与项目经理、检测检验报告（型式试验等）、制造商授权、**资质业绩凭证单（按分标）**

## 4. 评标办法实测（综合评估法）

- 分值构成在"前附表之三：评审办法一览表"中**按标包**指定所应用的技术/商务评分细则模板、权重、价格分算法、合同模板——即评分细则是**模板库 + 按包引用**的机制（福建样本直接给了模板 xlsx）。
- **价格分公式为多套模板之一**，样本含"区间平均价浮动法"等至少 5 种变体，共同骨架：剔除极值（按 M 分档去掉最高/最低若干个）→ 算术平均 A1 →（可能再剔除区间外报价）→ **基准价 = A × (1±c)**，浮动系数 c 由投标人代表与监察人**开标现场随机抽取**；价格分 = 100 − 100×n×|评标价−基准价|/基准价，高于/低于基准价用不同惩罚系数 n1/n2，负分取 0。→ 系统的价格模拟必须支持"参数化公式族 + c 不可知"的区间模拟，而非单点计算。
- **低于成本认定**（触发澄清）：报价 < 全部初评合格均值×50%，或 < 次低报价×50%，或 < 最高限价×45%。
- **限中标包数**：同一投标人在同一分标最多中 1 个包；多包同时第一优先授予金额大的包。→ 投标组合策略提示。
- 综合分相同：技术分高者优先，再报价低者优先。分值保留两位小数。

### 4.1 服务类评分细则模板（福建样本 xlsx 实测）

商务细则 FWSW01（服务类通用）：诚信评价（-60~0：不良行为-30/信用-10/影响公正性-20）+ 绿色低碳（绿电绿证 3）+ 科研创新 7（创新成果1/激励机制1/研发团队规模3：高级职称≥30人满分/科研经费占比2：任一年≥2%满分）+ **综合评价 90**（综合实力 26-36 + 投标响应 41-54，其中报价质量 29-30/27-28/…）。

技术细则模板库按业务线分（样本见 18 种编号）：`JS-FWTY 通用`、`JS-ZHFW01 科技项目`、`JS-GCZX01 工程咨询`、`JS-GCSG03 工程施工`…。以 JS-ZHFW01（科技项目）为例：总体评价 6-10、项目团队 10-30（负责人职称年限 + 团队职称学历人数分档）、**业绩 18-30（1 项合格 18 分，每多 1 项 +2，上限 +12）**、服务方案 1-5、进度保证 1-5、工作基础 0-10（产品化/成果/立项）、专利 0-5（每项 +1）、**绩效评价 1-5（按国网供应商绩效评价分数 ABCDE 分档，未参评 4 分）**。

→ 这证实了"评分项字典 + 结构化证据"路线：团队职称人数、业绩条数、专利数都是**可从企业库直接计数预测得分**的硬指标，模拟评分对服务类可以做到近乎确定性。

## 5. 技术规范书结构实测（物资）

标准三段式（与"通用/专用"假设对应但命名不同）：

```
1 标准技术参数表        ← 五列：序号|参数名称|单位|项目需求值或表述|投标人保证值（空，待填）
                          ★项需提供证明材料；一个物料几十行，含硬件规格与功能要求
2 项目需求部分          ← 2.1 货物需求及供货范围 2.2 备品备件/专用工具 2.3 文档资料提交
                          2.4 工程概况 2.5 项目单位技术偏差表
3 投标人响应部分        ← 3.1 投标人技术偏差表 3.2 销售及运行业绩表 3.3 备品备件响应
                          3.4 最终用户使用情况证明 3.5 测试报告表 3.6 鉴定证书表 3.7 应提供技术资料
```

系统要自动填的就是：**"投标人保证值"列**（从产品库取具体值，禁止"完全响应"）+ **第 3 部分全部表格**（业绩/报告/证书从库组装）。服务类规范书则是叙述式（总则/研究内容/成果形式/技术经济指标/进度/团队要求），对应"逐条需求响应"写法。

## 6. 投标文件成品结构（系统输出的目标形态）

样本中的真实投标文件（含一家供应商的已提交版本）证实：投标文件就是**严格按第六章格式目录逐节排布的单个 docx**（商务一个、技术一个），标题树与第六章一一对应，扫描件（营业执照、审计报告、证书、社保、合同+发票）作为图片插入对应小节。技术文件把技术规范书的"投标人响应部分"整体嵌入并填写。人员章节的固定套路：每人 = 身份证/学历证/职称证/资格证书/社保证明/劳动合同/服务项目 七件套。业绩章节：每项业绩 = 标题 + 合同扫描件 + 发票扫描件。

→ 文档引擎的输出规范可以直接照此实现；商务文件跨包复用（包14.包15.包16 一份文件），技术文件按包出。

**操作按钮流**（右上，即工具内标准工作流）：`编辑 → 生成 → 查看编辑 → 导出查看 → 加密提交 → 撤回`。顶部导航另有：任务列表（异步生成/加密任务）、投标情况汇总、常见问题。红字提示："请核实所需上传投标文件状态"、"严禁上传国家秘密"。

**对系统集成的结论**：

1. 与本系统的交接面就是"编辑"环节——系统产出各通道要求格式的 docx/pdf/附件，人在对应通道的编辑界面中挂载，然后走 生成→加密提交；"导出查看"可用于导出工具生成的完整投标文件做终审比对（本系统的合规审查 Agent 可对导出件做最后一遍全文校验）。
2. "撤回"存在说明截止前可撤回重传——系统的迭代修改流程（发现问题→改→重新导出）在工具侧有对应支撑。
3. 四通道模型最终确认：商务 / 价格 / 资质业绩 / 技术，与第六章"提交方式表"的端口列对应。
4. 仍待实操确认的仅剩：各通道"编辑"内页的具体表单（价格逐行填报页签、维护单价分析表）和 ECP 平台侧的凭证单生成页面。
